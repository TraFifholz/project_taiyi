# 主线设计：从头开始

本目录用于重新设计五章主线。旧稿已经移入：

- `campaign/archive/main-arc-scene-chain/`
- `campaign/archive/main-arc-20260604/`

后续 agent 不应引用旧稿作为可用方案。

## 当前固定点

- 开头固定：玩家死亡，阿瑶复苏，复活玩家角色；玩家在随缘事务所醒来。
- 结局固定：电子祭坛前的抉择。
- 五章主线可重写，旧方案全部可以推翻。
- 第五条故事线几乎确定是碳铀/人祭线。

## 设计目标

要交付的是创意种子和故事梗概，不是长篇章节详案。

梗概必须能支撑实际跑团的游戏量，但不需要在文件里写满遭遇、场景链、对白和具体团次流程。重点是情节骨架本身有没有承重能力。

玩家不是演员，也不是主动拯救城市的特工。先预设世界如何自己运转，组织和 NPC 如何行动，再说明玩家作为城市里的真实生活者，可能被迫撞进哪些裂缝。

## 章节文件必须包含

- 相关组织。
- 相关 NPC：允许新增，尽量复用；建议组织和 NPC 尽量 1:1 对应。
- 每个组织/NPC 在本章节内容中的一句话概括。
- 章节故事梗概。
- 相关故事线在本章暴露什么内容。
- 阿瑶追逐“呼唤自己的声音”的推进进度。

故事线进展必须使用四级标题：

```md
#### 故事线1进展
...

#### 故事线2进展
...
```

## 五章与故事线硬约束

- 章节首尾相接。
- 第 1 章接已知开头，处理并完结故事线 1，同时开始穿插故事线 2 和 3。
- 第 2 章处理并完结故事线 2，同时穿插故事线 3 和 4。
- 第 3 章处理并完结故事线 3，同时穿插故事线 4 和 5。
- 第 4 章处理并完结故事线 4，同时穿插故事线 5。
- 第 5 章处理并完结故事线 5，接电子祭坛结局。
- 所有组织/企业都必须至少在一个章节中出现并发挥作用。

## 写作禁忌

- 禁止上价值废话，例如抽象主题总结、城市隐喻、漂亮但没有行动信息的判断句。
- 禁止把玩家行动写成世界唯一发动机。
- 禁止把章节写成三流话剧剧本或连续场景链。
- 禁止用“PC 可以选择 A/B/C”替代组织/NPC 的主动行动。
- 禁止让 NPC 原地等玩家探索。
- 禁止为了显得详细而写长。短梗概优先。
