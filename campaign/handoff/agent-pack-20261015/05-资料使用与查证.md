# 资料使用与查证

## 先判断正在回答哪一种问题

| 问题 | 优先资料 |

| 某一场究竟说了什么 | `sources/records/README.md` 找原文件；摘要中的 `S14:L...` 指原文行号 |
| 某个人的真实身份、动机、幕后关系 | `sources/campaign/decisions/二十话重整-设计定案.md`、`npcs/stories/` 及对应参考册 |

| 后续主线 | `sources/campaign/episodes/20-episode-outline.md`、各话与人物故事；尚未跑出部分按设计读 |
| 当前奖励、奇能点和伤势 | `sources/records/memory/rules-and-rewards.md`、最近场次及实际角色卡；本包不含完整卡面 |

| 回到项目继续操作 | `sources/RUNBOOK.md`、`WORKSPACE.md`、`AGENTS.md` 及本地最新版本 |

## 事实与知情范围

1. **已发生**：原文明确动作和结算。能写作当前状态。
2. **NPC 口述、PC 推理、GM 场外说明**：保留说话者和性质。可以形成线索，不能直接当新取得的物证或全队知识。
3. **GM 定案**：人物真实身份、年代与动机。用来准备行动和回应，不自动由角色知道。
4. **未来预案**：触发、分支、场景与拟定结果。开团后按实际改写状态。

原始逐字稿决定实际发生了什么；后续摘要可修正先前提前口播的结果。当前定案与人物故事解释未公开的真相。旧稿保留检索价值，但不能因篇幅长、标题叫终稿就覆盖更新内容。

## 协作写法

优先复用已有 NPC。先查名录、故事和当前关系，再判断有没有必要新建人物。设计能力时看实际职业与来源，人物数值要依项目规则核查。已有规则、过去记录和未来安排分别维护。

故事正文写具体人物的目标、眼前发生的事、可取得的线索和行动后果。短场景保留能主持的内容，完整模组再展开数值与地图。给转述加引号会制造伪台词；用备团填补未跑场景会制造伪事实。两者都应避免。

本包没有新增剧情设定。接手 agent 的新想法先标“建议”，采用后再写入相应设定或准备文件；之后实际发生的结果才进 `records/`。修改原项目时保留原逐字稿和无关工作。
